## [0.10.0] (in progress)

### Milestone 14: every browser on every system

- `Chromium::launch_with_extension`: an ordinary Chrome or Edge (no
  debugging port, no automation switches) with a kept profile and the
  extension, driven through it. The whole Playwright API is tested through
  the extension (`tests/integration/extension_api.rs`); the extension now
  also handles cookies, permissions, downloads and popups' openers.
  Chromium pages restored from the back/forward cache, and pages attached
  after they loaded, count as loaded.

- A browser extension (`extension/`, TypeScript, WXT, MUI popup) lets the
  library drive the browser you already use, without remote-debugging
  mode. Chrome and Edge: the whole page API through
  `Chromium::connect_extension` / `Chromium::extension_relay(..).wait()`,
  with the browser's own profile as `contexts()[0]`. Firefox and Safari
  (no debugger for extensions): `ExtensionRelay::wait_pages()` gives
  `PageBrowser` / `PageTab` (tabs, `goto`, `evaluate`, click, fill,
  screenshot). `firefox::Browser::install_extension` installs an unpacked
  extension. Safari's build is produced but not yet tested on a Mac.

- New crate `chromiumoxide_webkit_protocol`: typed commands, responses,
  events and domain clients for WebKit's inspector protocol, generated by
  `chromiumoxide_pdl` from Playwright's WebKit `protocol.json` (all 33
  domains). The generator reads JSON protocol descriptions
  (`Generator::compile_protocol_json`, `pdl::parse_protocol_json`),
  merges per-platform duplicates, and can leave out the Chrome doc links
  (`Generator::docs_url(None)`). Chrome's generated code is unchanged.
  The WebKit engine sends its core commands typed through it, and a test
  checks every other WebKit method name it uses against the protocol.

- `Firefox::launch_server(_with)` and `WebKit::launch_server(_with)`
  (Playwright's `launchServer`, with `host`, `port`, `wsPath`): a browser
  other programs reach with `Firefox::connect` / `WebKit::connect`.

- Firefox and WebKit contexts take `bypassCSP`, `proxy` (with
  credentials), `clientCertificates` and `serviceWorkers: "block"`;
  WebKit also `javaScriptEnabled: false`. The client-certificate test
  server now takes several connections at once, as real servers do
  (WebKit opens one early, without a certificate).

- Firefox screenshots: `scale: "css"` (pixel-identical to Playwright's
  Firefox), WebP, `mask` / `maskColor`, and `omitBackground` (which
  Playwright's own Firefox does not implement). Checked: the library builds
  on its minimum Rust, 1.88.

- Firefox and WebKit now offer every public method of Playwright 1.65.1
  that Chromium does: 453 of 453 per `scripts/api_coverage.py`, each
  tested against the real browser (`tests/integration/firefox.rs`,
  `tests/integration/webkit_api.rs`). Where the engine cannot do one
  (`page.pdf` on WebKit, `requestGC` / `emulateMedia` / `download.cancel`
  on Firefox, CDP sessions on both), the method returns an error that
  says why. Highlights: frames as objects and the selector shortcuts;
  JSHandle / ElementHandle; live Request / Response objects; route
  `fallback` / `fetch`; `context.request`; context settings after
  creation; `exposeFunction` / `exposeBinding`; ARIA snapshots; clock;
  locator handlers; workers with `evaluate` on WebKit; tracing, HAR and
  `routeFromHAR` on WebKit; `routeWebSocket`; `browser.bind()` with
  `Firefox::connect` / `WebKit::connect`.

- Runs on Linux, Windows and macOS: the full suite passes on each with
  every browser required (Chromium, Chrome, Edge, Firefox, Playwright's
  WebKit, Electron, Tauri; real Safari on macOS).
- macOS editing commands (`domain::mac_editing`, Playwright's
  `macEditingCommands`): Backspace, Meta+A and the rest work in Chromium
  and WebKit on a Mac as under Playwright.

- `chromiumoxide::WebKit` and `chromiumoxide::webkit::{Browser,
  BrowserContext, Page}`: Playwright's WebKit build over its own protocol
  (`--inspector-pipe`). Contexts with emulation, goto, set_content,
  evaluate, style tags, resize, waits and screenshots pixel-identical to
  Playwright's WebKit.
- WebKit locators and input; `reload`, `goBack`, `goForward`; context
  cookies; `addInitScript` (context and page); `page.events()` with
  console messages, page errors and dialogs; `page.route` (fulfill,
  continue, abort), `context.route` and `unroute`; network events;
  `expect()` web-first assertions; frames (`frame_locator`, `frames()`);
  pop-ups; downloads; `recordVideo`.
- Firefox: `wait_for_url`, `wait_for_load_state`, `wait_for_request`,
  `wait_for_response`; locator `filter`, `and`, `or`, `all`,
  `bounding_box`, `evaluate`, `screenshot`; the `base_url` context option.
- `chromiumoxide::Safari`: Safari through `safaridriver` (WebDriver):
  goto, title, url, evaluate, waits, screenshots and CSS locators. Tested
  against WebKitGTK's WebDriver on Linux; Tauri on Linux shares the code
  (`WebDriverWindow`, `WebDriverLocator`).
- `LaunchOptions::browser_channel`: Playwright's `channel` (`chrome`,
  `msedge`, betas, devs, canaries), looked up where Playwright looks on
  each system. Tested with Microsoft Edge on Linux and Windows.
- Windows: launches use `--remote-debugging-pipe` like Playwright (the
  pipes travel on the C runtime's fds 3 and 4), so browsers quit with their
  parent; Firefox and the test helpers find Playwright's Windows and macOS
  folders; a reused profile's old DevTools port file is removed; the
  debugger finds call sites in Windows backtraces.
- `chromiumoxide::Tauri`: Tauri apps on Windows (WebView2 over CDP),
  Linux (WebKitGTK through WebKitWebDriver) and macOS (WKWebView through
  the app's embedded WebDriver server, `tauri-plugin-wdio-webdriver`,
  started with `TAURI_WEBDRIVER_PORT`). WebDriver `goto` waits for the
  load. `TauriWindow::WebKitGtk` is now `TauriWindow::WebDriver`.
- The whole suite runs on Windows 11 (Gary's PC).

### Milestone 12: every CDP domain

- `page.protocol()` and `browser.protocol()`: a typed client for every
  protocol domain, generated from the PDL (`chromiumoxide_cdp::cdp::domains`).
  One async method per command (`protocol().performance().get_metrics(..)`)
  and one typed stream per event (`protocol().network().on_request_will_be_sent()`),
  with the protocol's descriptions as docs: 57 domains, 634 commands, 224
  events. Deprecated items keep their raw types only.
- `chromiumoxide_types::CommandExecutor`: the trait the clients run on, for
  other sessions too.
- A coverage check fails when a command or event has no typed method or a
  domain has no integration test; `tests/integration/cdp_domains.rs` has one
  real-Chromium test per domain.
- `LaunchOptions::ignored_default_args`: Playwright's
  `ignoreDefaultArgs: [...]`, dropping single default switches (e.g.
  `--disable-extensions`); the default set is unchanged.
- Fixed: on Chrome for Android, a page without `<meta name=viewport>`
  (zoomed out to fit the screen) was screenshotted tiled 3x3; with no
  viewport option, screenshots now measure the ideal viewport. Desktop
  screenshots are unchanged. Found on a real emulator, where
  `examples/android_device.rs` now passes end to end.
- Fixed: required arrays were left out of the message when empty (the
  generator skipped them), so Chromium rejected calls such as
  `DOMSnapshot.captureSnapshot` with no computed styles or
  `Network.setCookies([])` as "Invalid parameters".

## [0.8.0] 2025-11-28

### Breaking Changes

Due to the support of new browsers in the fetcher, we changed the API.
The changes are mainly related to how you can request a specific version of the browser.
Previously you could only request a chromium revision, now we support chrome versions, channel and milestone.

```rust
BrowserFetcherOptions::builder()
  .with_kind(BrowserKind::Chrome)
  .with_version(BrowserVersion::Channel(Channel::Beta))
  .build()
```

We also change the output format of the `fetch`. It is now called a `BrowserFetcherInstallation`
and contains a `BuildInfo`. We garantee that at least the version or revision will be present
in that struct, but not always both.

```rust
let installation = chromiumoxide_fetcher::BrowserFetcher::new(options).fetch().await?;
println!("Executable path: {}", installation.executable_path.display());
```

Finally, we switched the async runtime tokio by default. We will remove for support for async-std in the next release.
If you want to part of the discussion on other runtime support, see [#273](https://github.com/mattsse/chromiumoxide/issues/273).
